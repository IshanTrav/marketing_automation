# Live Demo Commands

Run these in order, from inside the `automation/` folder. Each one prints something you can point at on screen. Full explanation of *why* each step exists is in `meta-setup-runbook.html` — this file is just the copy-paste sequence.

```bash
cd /mnt/sda2/D_backup/lez_aall/automation
```

---

## 1. Generate a video with Veo 3.1

```bash
npm run test-veo
```

Watches "Still processing..." for a minute or two, then saves `output_video.mp4` locally. This is the part your senior actually cares about seeing — a real AI-generated clip, not a placeholder.

---

## 2. Host it at a public URL

**What we're actually using today** (GCS credentials still pending):

```bash
git add -f output_video.mp4
git commit -m "demo video"
git push
```

Gives you: `https://raw.githubusercontent.com/IshanTrav/marketing_automation/main/output_video.mp4`

**The intended real path, once GCS creds are in `.env`:**

```bash
npm run upload output_video.mp4
```

Prints a `https://storage.googleapis.com/...` URL instead — same next steps either way.

## 3. Publish to Instagram

```bash
npm run publish-ig-video "PASTE_THE_VIDEO_URL_HERE" "Demo post — generated by Gemini/Veo, published via API"
```

Prints `Container created` → a few `Status: IN_PROGRESS` lines → `Published! Media ID: ...`. That ID is a real, live Instagram post.

To show a plain **image** post instead (faster, no processing wait):

```bash
curl -i -X POST "https://graph.instagram.com/v21.0/$IG_USER_ID/media" \
  -d "image_url=https://github.githubassets.com/images/modules/logos_page/GitHub-Mark.png" \
  -d "caption=Demo image post" \
  -d "access_token=$IG_ACCESS_TOKEN"
# copy the returned "id", then:
curl -i -X POST "https://graph.instagram.com/$IG_USER_ID/media_publish" \
  -d "creation_id=PASTE_CONTAINER_ID" \
  -d "access_token=$IG_ACCESS_TOKEN"
```

## 4. Publish to Facebook

```bash
npm run publish-fb-video "PASTE_THE_VIDEO_URL_HERE" "Demo video — generated by Gemini/Veo, published via API"
```

Prints `Published! Video ID: ...` directly (Facebook's video endpoint is one call, no polling needed).

For a quick **photo** instead:

```bash
npm run publish-fb-photo "https://github.githubassets.com/images/modules/logos_page/GitHub-Mark.png" "Demo photo post"
```

---

## 5. Prove it's real — pull the live link

Instagram:

```bash
curl -s "https://graph.instagram.com/PASTE_MEDIA_ID?fields=permalink&access_token=$IG_ACCESS_TOKEN"
```

Facebook:

```bash
curl -s "https://graph.facebook.com/PASTE_POST_ID?fields=id,permalink_url&access_token=$FB_PAGE_ACCESS_TOKEN"
```

Both return a clickable URL — open it in a browser tab right there in the meeting.

## One-time setup, only if `.env` isn't loaded into your shell yet

The npm scripts read `.env` themselves automatically — nothing needed there. The raw `curl` commands above use `$IG_USER_ID` / `$IG_ACCESS_TOKEN` / `$FB_PAGE_ACCESS_TOKEN` as shell variables, so load them first if you want to copy-paste those specific blocks:

```bash
export $(grep -v '^#' .env | xargs)
```
