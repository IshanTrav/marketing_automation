Meta API Setup Runbook

Every step we actually took to link Instagram + Facebook, create a Meta Developer App, get real access tokens, and publish a test image and video to both platforms — written down so it can be redone for Travafa's real account without relearning it.

Tested on: a personal sandbox account Result: image + video published on both platforms App Review needed: no (Standard Access)

A

Link Instagram to a Facebook Page

Do this before touching any developer tools — everything downstream depends on this link existing first.

  1. Create (or confirm) a Facebook Page — any personal Facebook account can create one for free, instantly.
  2. On the Instagram account: open the app → profile → ☰ menu → Settings and privacy → Account type and tools → Switch to professional account. Pick any category. When asked Creator or Business, pick Business.
  3. During that same flow, Instagram offers to connect a Facebook Page — pick the one from step 1. This does the linking in one shot.
  4. If you skipped that prompt, do it after the fact: profile → Edit profile → Public business information → Page → Connect or create.
  5. Confirm it worked: Edit profile → Public business information should show the Page's name next to "Facebook", and Category should show "Business".
What tripped us upThe "Account type and tools" screen does not show the Page-link status in newer Instagram versions — that moved to Edit profile → Public business information. Don't go looking for it in the wrong menu.
B

Register as a Meta Developer

A one-time activation on your existing Facebook login — not a separate account.

  1. Go to developers.facebook.com, log in with the same Facebook account that owns the Page from Part A.
  2. Click "Get Started" — this opens the registration dialog: Register → Verify account → Contact info → About you.
  3. Verify account asks for a phone number. Clicking "Send Verification SMS" may redirect you: "You can only complete this action in Accounts Center."
  4. If so, go to accountscenter.facebook.com → Profiles and personal details → Contact info → Add new contact → Add mobile number. When it asks which profiles to attach the number to, make sure your Facebook profile is checked, not just Instagram accounts.
  5. Back on the developer registration tab, continue — Contact info (confirm your email) → About you (pick any occupation, e.g. "Other") → Complete Registration.
What tripped us upOn the "Add a mobile number" screen, the checklist of accounts to attach the number to defaults to Instagram accounts only — the Facebook profile checkbox can be unticked. If it is, phone verification for the developer account never completes. Tick it explicitly.
C

Create the Developer App

  1. My Apps → Create App.
  2. Use cases step: filter by "Content management" (not "Featured") and select both:
    • Manage messaging & content on Instagram
    • Manage everything on your Page
  3. Business step: it auto-attaches to whichever Business Portfolio owns your assets. If none exists yet, one gets created automatically — this is fine for a Standard Access, no-App-Review setup.
  4. Requirements step: should say "No requirements for the use cases on this app" — if so, nothing to fill in.
  5. Overview step → Create app.
  6. On the app dashboard, go to App settings → Basic and copy the App ID and App Secret somewhere safe.
D

Grant yourself access (Roles)

  1. App roles → Roles — your own account should already show as Administrator (automatic, since you created the app).
  2. Click "Add People" → select role "Instagram Tester" (listed separately, under "Additional roles for this app") → search and add the Instagram account from Part A → send.
  3. Now switch to Instagram itself to accept the invite: Settings and privacy → search "Tester" in the settings search bar, or try instagram.com on the web if the app doesn't show it.
Known bug — this genuinely doesn't always show upMeta's own developer community has open threads about Instagram Tester invites never appearing in the mobile app at all, only reachable via web. If you search Instagram's settings and find nothing, try the web version at instagram.com before assuming you did something wrong. Confirm it's accepted by checking back on the app's Roles page — the "Pending" tag next to the tester's name disappears once accepted.
E

Turn on the permissions you need

Selecting a use case in Part C does not automatically enable every permission — each one has to be individually turned on.

Instagram sideApp dashboard → left sidebar → your Instagram product → API setup with Instagram login → section "1. Add required messaging permissions" → click "Add all required permissions" (adds instagram_business_basic, instagram_business_manage_comments, instagram_business_manage_messages). Then separately open Permissions and features in the same left menu, search instagram_business_content_publish, and click + Add — this one is not included in the "required" bundle but is what actually lets you publish.
Facebook Page sideApp dashboard → Use cases → Manage Pages → Permissions and features. Search each of these and click + Add until the Status column says "Ready for testing":
pages_show_listoften already "Ready for testing" by default
pages_read_engagementadd manually
pages_manage_postsadd manually — this is the one that actually publishes
Don't chase publish_videoAn old Facebook error ("No permission to publish the video") points at a permission called publish_video. It's deprecated and won't appear in any current permission picker. Ignore it — pages_manage_posts is genuinely enough for video too. If video publishing fails, the real cause is almost always the access token (see Part J), not a missing permission.
F

Get real access tokens

Instagram token — the easy oneApp dashboard → Instagram product → API setup with Instagram login → "2. Generate access tokens" (click the row to expand it if collapsed — it starts closed). Add your Instagram Tester account, generate the token, copy it. Also note your Instagram App ID shown near the top of this same page.
Your numeric Instagram User ID 
curl -i -X GET "https://graph.instagram.com/me?fields=id,username&access_token=YOUR_IG_TOKEN"
Returns {"id": "...", "username": "..."} — save that id.
Facebook Page token — the hard one, do it exactly this way
  1. Go to Graph API Explorer, select your app.
  2. Do not rely on GET /me/accounts — if your Page is managed through a Business Portfolio (likely), this returns {"data":[]} even though you have full access. This is a real Graph API quirk, not a permission problem.
  3. Under "User or Page" dropdown → click the "Get Page Access Token" text option (not the search box). This triggers a real "Facebook Login for Business" consent popup — "Continue as [your name]?" — accept it. This step matters: a token generated by just ticking permission checkboxes without going through this actual consent popup will look valid but silently fail to publish later.
  4. Make sure permissions pages_show_list, pages_read_engagement, pages_manage_posts are all checked before generating.
  5. Find your Page's numeric ID: business.facebook.com → Business Settings → Accounts → Pages → click your Page → the ID is shown in the panel / URL.
  6. Use the User token from step 3 to pull the Page's own token directly — this works even when /me/accounts doesn't: 
    curl -s -X GET "https://graph.facebook.com/YOUR_PAGE_ID?fields=access_token,name&access_token=YOUR_USER_TOKEN"
    The access_token in that response is the real Page Access Token — use this one, not the User token, for every publish call.
G

Test-publish to Instagram

Two-step for images, three-step for video (there's a processing wait in between).

Image 
curl -i -X POST "https://graph.instagram.com/v21.0/YOUR_IG_ID/media" \
  -d "image_url=<public image url>" \
  -d "caption=Test post" \
  -d "access_token=YOUR_IG_TOKEN"
# returns a container id, then:
curl -i -X POST "https://graph.instagram.com/YOUR_IG_ID/media_publish" \
  -d "creation_id=CONTAINER_ID" \
  -d "access_token=YOUR_IG_TOKEN"
Video / Reel 
curl -i -X POST "https://graph.instagram.com/v21.0/YOUR_IG_ID/media" \
  -d "media_type=REELS" \
  -d "video_url=<public video url>" \
  -d "caption=Test video" \
  -d "access_token=YOUR_IG_TOKEN"
# poll until finished:
curl -i -X GET "https://graph.instagram.com/CONTAINER_ID?fields=status_code&access_token=YOUR_IG_TOKEN"
# when status_code = FINISHED:
curl -i -X POST "https://graph.instagram.com/YOUR_IG_ID/media_publish" \
  -d "creation_id=CONTAINER_ID" \
  -d "access_token=YOUR_IG_TOKEN"
What tripped us upWikipedia/Wikimedia image URLs get rejected — "media file could not be downloaded from this URI" — because Wikimedia blocks bot-style fetch requests. Any plain static asset host works fine (we used a GitHub-hosted image and raw video file successfully).
H

Test-publish to Facebook

Photo — one call 
curl -i -X POST "https://graph.facebook.com/v26.0/YOUR_PAGE_ID/photos" \
  -d "url=<public image url>" \
  -d "caption=Test photo" \
  -d "published=true" \
  -d "access_token=YOUR_PAGE_TOKEN"
Video — one call, hosted-URL flow 
curl -i -X POST "https://graph.facebook.com/v26.0/YOUR_PAGE_ID/videos" \
  -d "file_url=<public video url>" \
  -d "description=Test video" \
  -d "published=true" \
  -d "access_token=YOUR_PAGE_TOKEN"
Note the field is file_url here, not video_url like Instagram uses.
Confirming a post actually existsDon't just scroll the Page looking for it. Query it directly: 
curl -s -X GET "https://graph.facebook.com/YOUR_POST_ID?fields=id,permalink_url&access_token=YOUR_PAGE_TOKEN"
Returns a direct link you can open in a browser. Also: the Page ("IshanTravafa") and your personal profile ("Ishan Travafa") can have near-identical names — make sure you're looking at facebook.com/YOUR_PAGE_ID, not your own personal timeline.
